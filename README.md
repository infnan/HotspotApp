# 热点开关（Android 7）

适用于 Android 7.0 / 7.1（API 24 / 25），原生 Java，无第三方运行时依赖。当前版本 1.5，安装包位于 dist/HotspotToggle.apk。

## 当前工作方式

- 开启：打开系统热点设置，由辅助功能服务识别热点开关并点击。检测到系统热点状态为已开启后，执行返回桌面。
- 关闭：沿用 1.0 的 WifiManager.setWifiApEnabled(null, false)，等待系统确认关闭，不进入设置页面，不依赖辅助功能服务。
- 不再调用 getTetherableWifiRegexs、startTethering 或其他会触发已知 MANAGE_USERS / CREATE_USERS 用户查询错误的网络共享接口。
- 失败时显示可滚动的调试弹窗，一键复制完整异常、设备和授权信息。无法识别系统页面时，错误中附带该设置页面的文字和控件 ID；请检查内容后再分享。

## 安装和授权

1. 覆盖安装 dist/HotspotToggle.apk，保留原来的修改系统设置授权。首次未授权会打开系统授权页面，允许后再次触发。
2. 热点关闭时，若辅助服务未连接，应用打开辅助功能设置。手动启用“热点开关辅助服务”，返回后再次触发；首次授权不会自动切换热点。
3. 开启前点亮屏幕并解锁。应用会短暂显示系统热点设置，点击热点开关，确认开启后回到桌面。
4. 再次触发应用，通过旧接口关闭热点。

辅助服务由 Android 管理，启用后保持可用，但只在用户触发开启的短时任务中操作界面。它只接收 com.android.settings 的窗口事件，不操作辅助功能授权开关；不使用悬浮窗，不申请 Root。

## 页面识别与限制

- 优先打开 com.android.settings.TetherSettings，失败后进入无线设置，尝试识别中文或英文的热点菜单和开关。
- 只识别与热点标签关联的可勾选控件，或热点页面的系统 SwitchBar；开启按钮最多成功点击一次，避免重复点击把热点关闭。
- 页面导航最多四次；整体辅助操作最多约 25 秒，工作线程最多等待 27 秒。关闭热点最多等待 20 秒。
- 厂商页面布局、标签、包名或确认对话框可能不同；当前不猜测任意坐标、不自动接受未知确认框。不匹配时保留系统页面并报告失败。
- 开启成功仅表示系统热点状态为已开启，不表示已验证 DHCP 地址分配。实际共享走用户已经验证可用的系统设置路径，但仍需在 PDC680 上确认辅助点击效果及客户端自动获取 IP、DNS 和访问互联网。
- 本版尚未连接 PDC680 做真机测试。锁屏或息屏开启不受支持；关闭仍走后台接口。
- 关闭不自动恢复普通 Wi-Fi。开启前 Wi-Fi 的处理由系统设置流程负责。

## 构建

使用 JDK 17 或 21、Android SDK Platform 35、Build Tools 35.0.0：

~~~powershell
.\tools\build-apk.ps1
~~~

脚本使用 ANDROID_HOME 或项目 .tools/android-sdk，可通过 -SdkPath 和 -JdkPath 指定工具位置。APK 使用现有本地调试密钥，输出到 dist/HotspotToggle.apk，并验证签名和 ZIP 对齐。最低 API 为 24、目标 API 为 25。

也可通过 Android Studio 或 Gradle 构建：

~~~powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug
~~~

本版以独立脚本构建为验证依据，未把 Gradle / lint 或真机测试计为通过。

## 真机复测

1. 从旧版覆盖安装，确认应用版本为 1.5，设置原来的热点名称和密码。
2. 系统设置关闭热点；未启用辅助功能时触发，只应打开授权页。启用后再次触发，观察热点开关是否被正确点击，随后回桌面。
3. 客户端使用自动获取地址，确认获得 IP、网关、DNS，并能访问互联网。
4. 热点开启后停用辅助服务，再触发应用，确认旧接口仍能关闭热点。
5. 连续快速触发时提示切换中，不重复点击开关。
6. 开启时锁屏、页面不匹配、启动失败和超时均显示可复制错误，不误报成功。
7. 确认蓝牙共享、USB 共享、热点密码等其他控件没有被操作。

入口为 com.example.hotspottoggle/.ToggleActivity。旧版本原理和 PDC680 用户查询权限问题见 docs/PDC680-investigation.md；只读设备采集脚本为 tools/collect-device-diagnostics.ps1。
